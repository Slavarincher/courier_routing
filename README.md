# ЭС «Маршрут курьера» - прототип экспертной системы (ЛР №6)

Экспертная система выбора и корректировки маршрутов курьеров службы доставки.
Предметная область 1.11. Веб-приложение на Python + Flask, работает локально, интернет не нужен.

## Запуск

Нужен Python 3.8 или новее.

**Windows:** дважды щелкнуть `run.bat`.

**Вручную:**
```
pip install -r requirements.txt
python app.py
```
Затем открыть в браузере http://localhost:5000

Тесты (контрольный пример из ТЗ, п. 6.6):
```
python -m unittest -v
```

## Как это работает

1. При запуске `ExpertSystem` загружает онтологию (`.pont`/`.pins`) и правила (`rules.json`).
   Заказы, курьеры, транспорт, зоны и дорожная обстановка на экране 1 берутся из экземпляров онтологии.
2. Диспетчер нажимает «Построить маршрут» - интерфейс вызывает один метод `ExpertSystem.plan(shift)`.
3. Машина вывода работает в два этапа:
   * **анализ данных** - правила 1, 3, 5, 6, 7, 9, 10, 13: срочные заказы, пробки и перекрытия,
     курьеры без автомобиля, зоны с ограничением въезда, близкие заказы, низкий рейтинг;
   * **проверка плана** - правила 2, 4, 6, 13, 14: перегруз, опоздания, нет подходящего курьера,
     окончание смены.
4. Модуль маршрута строит 2-3 варианта (приоритетный с объездом, через пробку, кратчайший),
   оценивает их и выводит объяснение - какие правила сработали.
5. На экране 3 события «доставлен», «клиент недоступен», «отклонение», «перекрыта дорога»
   передаются в `ExpertSystem.handle_event(...)` - срабатывают правила 8, 10, 11, 12.

## Замена Базы Знаний

Файлы `kb/CourierRouting.pont` и `kb/CourierRouting.pins` можно открыть в Protégé 3.5
(проект «Protégé Files (.pont and .pins)»), изменить и сохранить обратно в папку `kb/`.
При добавлении нового заказа в онтологию его адрес должен быть в `data/geo.json`.

## Демонстрация (сценарий)

1. Экран 1 → «Построить маршрут». Петров (автомобиль) получает 1001 → 1002 с объездом пробки,
   Сидоров (велосипед) - 1003 → 1004 в пешеходной зоне.
2. Экран 2 → посмотреть «Почему вариант A» и предупреждение по варианту C → «Утвердить».
3. Экран 3 → «Сообщить о проблеме»: отклонение 2 км (правило 8) или перекрытие дороги (правило 10).
4. «Заказ доставлен» / «Клиент недоступен» → маршрут завершается (правила 11, 12).
5. Экран 1 → добавить срочный заказ (ул. Ложинская, 5, высокий) → «Построить маршрут»:
   он уходит свободному курьеру поблизости (правило 9).
6. Ошибки ввода: неизвестный адрес, вес -5, окно 12:00-11:00 - поля подсвечиваются.
